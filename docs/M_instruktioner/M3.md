M3 – Containeriserad

    Inlämningsdatum 15 Sep av 23.59 Poäng 0 Lämnar in en textimatningsruta

Fjärde milstolpen i Kraftly-projektet. Målet: portalen finns som ett paket som kör likadant överallt. Det pipelinen bygger i M2 – artefakten dist – ska från och med nu paketeras i en image tillsammans med en webbserver, och docker compose up ska starta hela den lokala miljön: frontend och mock-API. Det är det paketet, inte er källkod, som ska ut i molnet i vecka 5.

M3 är den första milstolpen för er andra tech lead (period 2, v. 4–6).
Definition of Done

Bocka av i docs/milestones.md under rubriken M3. Alla punkter ska vara uppfyllda på main när taggen sätts.

    Multi-stage Dockerfile i repots rot: byggsteg med Node, serveringssteg med nginx. Ingen Node och ingen node_modules i den färdiga imagen
    .dockerignore med minst node_modules, dist och .git
    nginx.conf med SPA-fallback – omladdning på /fakturor ger appen, inte 404
    Imagen är under 100 MB – skärmdump av docker image ls i docs/containers.md. Har du två storlekskolumner gäller DISK USAGE, den första
    docker compose up --build från ett rent klon startar frontend (localhost:8080) och mock-API, och man kan logga in och se dashboarden
    docker build som eget jobb i CI (image), grönt på main, med imagens storlek i loggen
    docs/containers.md enligt mallen från workshopen: hur man kör, storlekstabell med uppmätta siffror (minst naiv vs. multi-stage), tre beslut (basimage · hur mock-API:t körs · hur browsern når API:t), vad som körs i CI, kända begränsningar
    README Getting started omskriven: ett sätt med Docker, ett utan – och npm start-felet borta (skulden från M0)
    Logg i docs/log.md: en post per arbetsdag, inklusive vem som gjorde vad. Ny tech lead presenterad i loggen

Valfritt (räknas inte i DoD, men underlättar M4): frontenden anropar /api relativt med proxy i Vite och nginx i stället för hårdkodat localhost:4000 · imagen pushas till GitHub Container Registry från pipelinen.

Vanliga missar – kolla innan ni taggar

    docker compose up fungerar hos den som skrev filen men inte i ett rent klon → något ligger i .gitignore (nginx.conf?) eller bygger på en lokal image. Testa i /tmp
    Inloggningen fungerar i npm run dev men inte i containern → browsern når inte API:t: porten 4000:4000 är inte publicerad, eller så pekar proxyn på localhost i stället för api
    Omladdning på /fakturor ger nginx 404 → try_files saknas, eller nginx.conf kopieras till fel sökväg (det är /etc/nginx/conf.d/default.conf)
    Imagen är 200+ MB → ni serverar med Node (vite preview) i stället för nginx, eller så saknas det andra FROM-steget
    npm ci failar i bygget med "lock file … not in sync" → samma fel som i CI, samma orsak: committa package-lock.json
    transferring context tar en halv minut → .dockerignore saknas eller är felstavad (det är .dockerignore, inte .dockerignore.txt)
    Ändringen syns inte efter docker compose up → ni ändrade Dockerfilen men körde utan --build
    CI-jobbet image failar men bygget fungerar lokalt → Dockerfilen kopierar en fil som bara finns på er dator (.env?), eller så är filnamnets skiftläge fel – Linux-runnern bryr sig
    Mac med Apple Silicon: imagen är byggd för arm64. Det spelar ingen roll ännu – men det kommer att spela roll i vecka 5. Skriv upp det under Kända begränsningar
    docs/containers.md förklarar vad Docker är i stället för era val och era siffror – tabellen och de tre besluten är det som räknas
    Taggen satt när pipelinen på main är röd – då är ni per definition inte klara
