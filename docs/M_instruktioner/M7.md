    export const debounce = (fn, ms) => {
      let timer
      return (...args) => {
        clearTimeout(timer)
        timer = setTimeout(() => fn(...args), ms)
      }
    }

Spår 3 · Budgeten och servern (1 pers)

Mål: budgeten vaktas av pipelinen, och nginx komprimerar.

    lighthouserc.json i repots rot:

    {
      "ci": {
        "collect": {
          "startServerCommand": "npm run preview",
          "startServerReadyPattern": "Local",
          "url": ["http://localhost:4173/login"],
          "numberOfRuns": 3
        },
        "assert": {
          "assertions": {
            "largest-contentful-paint": ["error", { "maxNumericValue": 2500 }],
            "cumulative-layout-shift": ["error", { "maxNumericValue": 0.1 }],
            "resource-summary:script:size": ["error", { "maxNumericValue": 60000 }],
            "total-blocking-time": ["warn", { "maxNumericValue": 200 }],
            "categories:performance": ["warn", { "minScore": 0.9 }]
          }
        },
        "upload": {
          "target": "temporary-public-storage"
        }
      }
    }

    "error" gör körningen röd, "warn" varnar. JavaScript-taket är i byte (60000 = 60 kB över nätet). Inga kommentarer i JSON. Lägg .lighthouseci/ i .gitignore.
    Sätt ert eget tak. Kör lokalt när spår 2 mergat lazy routes: npm run build && npx --yes @lhci/cli@0.15.x autorun. Rapporten i .lighthouseci/ visar vad /login faktiskt hämtar. Sätt maxNumericValue för JavaScript strax över er siffra – inte högre än nödvändigt, och inte under den. Innan spår 2 är klart kommer budgeten att vara röd: det är rätt, den ska säga nej till den gamla koden.
    CI-jobbet i .github/workflows/ci.yml, efter e2e, före publish:

      lighthouse:
        name: Prestandabudget (Lighthouse)
        runs-on: ubuntu-latest
        needs: build
        steps:
          - uses: actions/checkout@v4
          - uses: actions/setup-node@v4
            with:
              node-version: 22
              cache: npm
          - run: npm ci
          - uses: actions/download-artifact@v4
            with:
              name: dist
              path: dist
          - run: npx --yes @lhci/cli@0.15.x autorun

    och i publish: needs: [quality, e2e, lighthouse] – ingen image utan godkänd budget. Heter ert byggjobb eller er artefakt något annat än build/dist: använd era namn.
    Required check. Settings → Branches → regeln för main → Require status checks to pass → lägg till Prestandabudget (Lighthouse) (den syns i listan först när jobbet kört en gång). Samma sak som ni gjorde med lint och test i M2.
    Komprimering. Kolla först om staging redan komprimerar:

    curl -sI -H 'Accept-Encoding: gzip, br' https://<er-staging>/assets/<en index-fil>.js | grep -i content-encoding

    Hittar ni filnamnet i curl -s https://<er-staging>/ | grep -o 'assets/index-[^"]*js'. Står det content-encoding: gzip eller br: plattformen gör det redan – skriv det i dokumentet. Står det ingenting, lägg till i server-blocket i nginx.conf.template (efter server_tokens off;):

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;
    gzip_vary on;

    Mät med curl -s -o /dev/null -w "%{size_download}\n" -H 'Accept-Encoding: gzip' <url till js-filen> före och efter (lokalt med docker compose up --build, eller i staging efter deploy).

Klart när: jobbet Prestandabudget (Lighthouse) körs på varje PR, är required, blir rött om budgeten bryts, och ni vet om era JS-filer går komprimerade över nätet.
