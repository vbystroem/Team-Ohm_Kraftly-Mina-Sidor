Tre ändringar. Överst, direkt efter const express = require('express'):

// Konfiguration kommer från miljön. Lokalt läses .env (om den finns).

process.loadEnvFile()

// ingen .env – helt normalt i en container

// API_KEYS = flera klienter, en nyckel var: "volt:abc123,ampere:def456"
// API_KEY = en enda nyckel (det räcker lokalt)
const keys = new Map(
(process.env.API_KEYS || (process.env.API_KEY ? `lokal:${process.env.API_KEY}` : ''))
.split(',')
.map((entry) => entry.trim())
.map((entry) => [entry.slice(0, entry.indexOf(':')), entry.slice(entry.indexOf(':') + 1)])
.filter(([name, key]) => name && key)
.map(([name, key]) => [key, name])
)
if (keys.size === 0) {
console.error('API_KEY saknas. Lokalt: kopiera .env.example till .env. I molnet: sätt variabeln hos plattformen.')
process.exit(1)
}

Efter CORS-blocket (det som slutar med next() och })):

1.5 nginx.conf blir en mall

cat > nginx.conf.template <<'EOF'

# MALL – nginx-imagen fyller i ${PORT}, ${API_URL} och ${API_KEY} från miljön när

# containern startar. Saknas en variabel vägrar nginx starta.

server {
listen ${PORT};
root /usr/share/nginx/html;
index index.html;

location / {
try_files $uri $uri/ /index.html;
}

# /api skickas vidare – och nyckeln läggs på här, på servern.

location /api/ {
proxy_pass ${API_URL}/api/;
    proxy_set_header X-Api-Key ${API_KEY};
proxy_ssl_server_name on; # krävs när API_URL är https
proxy_read_timeout 90s; # test-API:t kan sova – första anropet tar upp mot en minut
}
}
EOF

M4 – Continuous Delivery

    Inlämningsdatum 22 Sep av 23.59 Poäng 0 Lämnar in en textimatningsruta

Mål: en merge till main är hela releasen. Pipelinen bygger portalens image en gång, pushar den till GitHub Container Registry och deployar exakt den till staging – och säger inte att den är klar förrän staging faktiskt kör den nya versionen. Samtidigt betalar ni av skulden som legat i repot sedan byrån: API-nyckeln i src/services/api.js. Den ska bort ur koden, och nyckeln ni använder i stället ska ligga på ett enda ställe, där browsern aldrig ser den.

M4 är den andra milstolpen för er andra tech lead (period 2, v. 4–6).
Definition of Done

Bocka av i docs/milestones.md under rubriken M4. Alla punkter ska vara uppfyllda på main när taggen sätts.

    Nyckeln ut ur koden: ingen API-nyckel i src/ och inga hemligheter i VITE_-variabler. Appen anropar /api relativt, och nginx lägger på X-Api-Key från miljön (nginx.conf.template)
    Den gamla nyckeln är död – och ni har bevisat det: curl mot test-API:t med nyckeln från api.js ger 401, och utskriften står i docs/deploy.md. Teamets nya nyckel finns bara i Render
    Lokalt fungerar som förut: .env.example i repot, .env i .gitignore och .dockerignore. Från en ren klon: cp .env.example .env + docker compose up --build → man kan logga in
    Bygg en gång: pipelinen bygger imagen en gång per commit och pushar den till GHCR taggad med commitens sha – bara från main, aldrig från en PR
    Automatisk deploy till staging: merge till main deployar till Render via deploy hook. Hooken ligger som secret i GitHub-miljön staging, adressen som variable. Ingen klickar i Render för att släppa en version
    Verifierad deploy: deploy-jobbet väntar tills /version.txt visar commitens sha och gör sedan ett röktest mot /api – jobbet blir rött om något av dem misslyckas
    Miljökonfig via variabler: API_URL och API_KEY sätts i Render, inte i imagen. Samma image kör lokalt i compose
    docs/deploy.md enligt mallen från workshopen (flöde, miljöer, var varje variabel bor, nyckeln, rollback, uppmätta tider, kända begränsningar) + beslutsdokument docs/decisions/hosting.md med minst tre jämförda alternativ
    README med staging-adressen och Kom igång som börjar med cp .env.example .env · logg i docs/log.md, en post per arbetsdag, med vem som gjorde vad

Valfritt (räknas inte i DoD): skriv om git-historiken så att den gamla nyckeln försvinner ur repot (git filter-repo) – och skriv i docs/deploy.md varför det inte ersätter rotationen · rollback-workflow med valfri sha (övning 2 A) · miljöbanner via config.js (övning 2 B – krävs i M5).

Vanliga missar – kolla innan ni taggar

    Nyckeln är borttagen ur api.js men ligger nu i .env som VITE_API_KEY → den bakas in i dist/ igen. Kör npm run build && grep -r "<nyckel>" dist/ – inget ska hittas
    Nyckeln togs bort i en commit men roterades aldrig → den finns kvar i historiken och i alla kloner. Rotationen är det som räknas; curl-beviset i deploy.md visar den
    docker compose up fungerar hos er men inte i en ren klon → .env saknas där (den ska saknas – det är därför README börjar med cp .env.example .env)
    Render-loggen säger nginx: [emerg] unknown "api_key" variable → API_KEY saknas eller är felstavad i Render. nginx vägrar starta utan den – det är meningen
    host not found in upstream "api" i Render-loggen → imagen byggdes innan nginx.conf blev en mall (spår 1 inte mergat), eller API_URL pekar på http://api:4000, som bara finns i compose
    Inloggningen ger 401 på staging men fungerar lokalt → Render har labbnyckeln eller en gammal nyckel, inte teamnyckeln
    Inloggningen ger 404 → snedstreck sist i API_URL. 502/504 → fel adress, eller test-API:t sover – vänta en minut
    Render kan inte hämta imagen (unauthorized, pull access denied) → paketet i GHCR är privat, eller Image URL har versaler
    Deploy-hooken ger 400 → imagen i anropet heter inte samma sak som tjänstens Image URL (bara taggen får skilja)
